# Replacing Flagship Specialists with RL-Only Fine-Tuned Specialists: A Design Problem on 1×A100 and N×A100

ARIA's specialist network is $\mathcal{M} = \{M_{\text{query}}, M_{\text{retrieve}}, M_{\text{read}}, M_{\text{code}}, M_{\text{verify}}, M_{\text{critic}}\}$. Of these six, two are not fine-tuning candidates at all under any version of this plan: $M_{\text{retrieve}}$ is not a model, it is a deterministic pipeline of sparse scoring, dense cosine similarity against fixed embeddings, and reciprocal rank fusion, with no learned parameters anywhere in it; $M_{\text{verify}}$ is the judge, a rule-based rubric and gate cascade that produces the very reward signal everything else is trained against, and turning the judge into a trainable policy scored by its own verdicts is circular by construction, not a harder version of the same problem. That leaves four real candidates: $M_{\text{query}}$, already replaced by a QLoRA-adapted DeepSeek-R1-Distill-Llama-8B trained by GRPO with no supervised fine-tuning stage and no labeled data, verified this session to actually be the model doing the work rather than a hosted flagship, on both routing grounds and physical grounds, three checkpoints with three different MD5 hashes at three points in training; $M_{\text{code}}$, currently a hosted flagship reached over OpenRouter, with reward machinery already mature, sandbox execution, static validation, and a paper-fidelity rubric that already penalizes generic-fallback substitution, none of it newly built for this plan; $M_{\text{read}}$, currently a hosted flagship, with reward machinery that checks internal well-formedness of the extracted spec and checks the generated code against the spec, but checks nothing about the spec against the source paper, a gap already present in the deployed system today, not introduced by training against it; and $M_{\text{critic}}$, currently a hosted flagship, a binary approve/reject gate on a completed candidate rather than an open-ended generator, structurally closer to $M_{\text{verify}}$ in character than to the other three, untried as an RL target and not analyzed further here. The philosophy under examination is replacing all four, one at a time, with small locally-trained specialists optimized purely by reinforcement learning against ARIA's own existing reward decomposition, no SFT stage, no curated demonstration data, on the model that ARIA's own architecture rents: one NVIDIA A100, 40GB, then some integer multiple of that unit.

The math that already exists and is already verified end to end, once, for $M_{\text{query}}$, is the foundation everything below is built on rather than a separate concern. A trajectory is $\tau = (s_0, q_0, o_0, \ldots, s_T, q_T, o_T)$, where $s_t$ carries the cleaned dataset profile $z$, the structured hypothesis $h$, and the sequences of prior queries, retrieved slates, extracted specs, generated programs, execution outputs, and gate verdicts accumulated so far. The terminal reward is a clipped, order-preserving, non-injective projection of a tree-valued validation object, $R(\tau) = \operatorname{clip}_{[0,1]}(B(\tau) + A(\tau) - \Lambda(\tau))$, where $B(\tau)$ takes one of two forms depending on whether the paper-program implementation hard gate survives, $0.50\,I(\tau)$ if it fails, $0.30\,I(\tau) + 0.45\,D(\tau) + 0.25\,V(\tau)$ if it does not, and the validation tree itself is an ordered, non-compensable cascade $g_0, g_1, \ldots, g_6$ over hypothesis validity, estimand binding, data applicability, multiplicity control, execution success, paper-program fidelity, and assumption admissibility, short-circuiting to the first failed gate and reaching \texttt{survivor} status only if every one of the six passes, robustness measured and emission permitted only past that point. A training round draws $K$ dataset contexts and $G$ i.i.d. rollouts per context from the frozen parameters $\theta$ in force at the start of the round, and the credit assigned to rollout $g$ of context $k$ is leave-one-out over the other $G-1$ rollouts sharing that exact context, $\hat A^{(k,g)} = R(\tau^{(k,g)}) - \frac{1}{G-1}\sum_{g' \neq g} R(\tau^{(k,g')})$, which is proved unbiased by conditioning on the sigma-algebra generated by the other $G-1$ draws, a quantity that does not depend on the action being scored, so the score-function identity $\mathbb E_{\tau^{(k,g)}}[\nabla_\theta \log \pi_\theta(\tau^{(k,g)})] = 0$ makes the correction term vanish exactly. The mechanism this replaced, a baseline conditioned on the trajectory's own realized terminal gate, is proved biased by the same tool used in reverse: because the gate $G(\tau^{(k,g)})$ is an outcome of the very trajectory being scored rather than a state fixed before that trajectory is sampled, the identity $\mathbb E_\tau[b(G(\tau))\nabla_\theta \log \pi_\theta(\tau)] = \nabla_\theta \sum_g b(g)\,P_\theta(G=g)$ does not collapse to zero, and once the baseline tracks $\mathbb E[R\mid G=g]$, that residual becomes $\nabla_\theta \mathbb E_\tau[R(\tau)]$, the entire true gradient, cancelling almost exactly the cross-gate signal that lets a query policy learn to land on better gates more often. This proof is not specific to the query policy; nothing in its derivation refers to what kind of action is being scored, only that the baseline must be constructed from draws that share the scored sample's context without including the scored sample's own outcome. It transfers to any specialist $M_j$ verbatim, provided the same structural condition is met, $G \geq 2$ i.i.d. samples of $M_j$'s action from a context that is genuinely fixed across those $G$ draws.

That last clause is where the plan stops being a straightforward generalization and starts accumulating real mathematical debt. "Context fixed across the $G$ draws" is trivial for $M_{\text{query}}$ because the query is the first decision in the trajectory, the context is just the dataset profile, deterministic, computed once, identical across all $G$ rollouts of a round by construction. It is not trivial for $M_{\text{code}}$, whose context is the extracted method spec, itself the output of $M_{\text{read}}$; nor for $M_{\text{read}}$, whose context is the retrieved paper, itself the output of a query that was itself sampled from $M_{\text{query}}$. If $M_{\text{query}}$ is also being trained, or even just resampled stochastically at temperature $>0$ round to round, the context feeding $M_{\text{read}}$ is not fixed, it is drawn from a distribution that is itself shifting, and the leave-one-out baseline for $M_{\text{read}}$ silently stops satisfying the condition its own unbiasedness proof requires. Formally, for two specialists $j$ and $j'$ with $j$ upstream of $j'$ in the pipeline order, if $M_j$'s parameters $\theta_j$ are updated at round $t$, the distribution over $j'$'s context, $P_{\theta_j^{(t)}}(\text{context}_{j'})$, changes with $t$, so the environment $j'$ is training against satisfies $P_t(R \mid a_{j'}, s) \neq P_{t+1}(R \mid a_{j'}, s)$ whenever $t$ indexes a round in which any upstream specialist also moved. This is not a heuristic worry about confounding, it is the exact condition, formalized once already in this project for the single-specialist case, under which the leave-one-out correction term stops vanishing. The isolated-arm prescription, train one specialist per experimental arm with the other three frozen at their current baseline, follows from this as a corollary of an already-proved theorem rather than as an independently justified piece of engineering hygiene: freezing $M_{-j}$ is not merely a way to attribute credit cleanly after the fact, it is the precondition for the advantage estimator used to train $M_j$ to be unbiased at all. Five arms training against one shared, simultaneously-adapting pipeline is not a more ambitious version of the one-specialist design ARIA already runs, it is a design whose gradient estimator has no proof behind it, because the theorem that licenses leave-one-out advantage estimation does not survive a moving upstream policy.

A second bottleneck is a direct, formal consequence of the non-compensable cascade rather than a separate phenomenon, and it explains why a per-specialist causal effect measured at the terminal reward can read as zero even when the specialist genuinely improved. Write the terminal gate reached by a trajectory as a function of the joint action vector across specialists, $G(a_{\text{query}}, a_{\text{read}}, a_{\text{code}}, \ldots)$, and consider replacing $M_j$'s baseline behavior with a fine-tuned $\widetilde M_j$ while holding every other specialist at its frozen baseline $M_{-j}^0$. The measured effect at gate $k$ is $\Delta_{j,k} = P(G_k = 1 \mid \widetilde M_j, M_{-j}^0) - P(G_k = 1 \mid M_j^0, M_{-j}^0)$, and because the cascade short-circuits at the first failed gate, $\Delta_{j,k}$ can only be nonzero for gates $k$ that a trajectory actually reaches, which is itself gated by every earlier check passing. If $M_j$'s stage sits downstream of a gate that some other, untrained part of the pipeline fails at high and roughly constant rate, for instance the majority of $M_{\text{code}}$'s rollouts against the current frozen baseline stopping at the implementation gate before $g_5$ or $g_6$ are ever evaluated, then fine-tuning $M_{\text{read}}$ to produce measurably better specs by every internal metric can leave $\Delta_{\text{read},k}$ near zero at every downstream gate simply because those gates were rarely being reached at all, by either condition. The terminal scalar reward, and even the gate-indexed vector, is not a neutral measuring instrument here; it is itself shaped by the cascade's own non-compensable structure, so an isolated-arm experiment can return "no measurable effect" for a specialist that is genuinely better, purely because a different, unrelated stage remains the binding constraint. The corrective is not a different reward, the current reward decomposition is the right one for the reasons already established in this project's own limitations analysis, the corrective is that $\Delta_{j,k}$ has to be read jointly with the marginal occupancy of every gate at or before $j$'s own stage, which the matrix formulation already anticipates in shape but which needs this masking mechanism made explicit rather than left implicit, or a real improvement will be reported as a null result, or worse, a real null result at a masked gate will be mistaken for a failed specialist.

A third bottleneck is specific to $M_{\text{read}}$ and is not hypothetical, it is already documented, unresolved, in this project's own evaluation record: nothing in the current reward checks a claimed algorithm step or assumption against the actual text of the source paper, only against internal well-formedness and against the code generated downstream of it. Formalize the reward $M_{\text{read}}$ would be optimized against as some $\rho(\text{spec}) = f(\text{coverage}, \text{internal\_consistency}, \text{downstream\_code\_fidelity})$ with no term $F_{\text{grounding}}(\text{spec}, \text{paper\_text})$ anywhere in $f$. There is no mathematical reason for $\arg\max_\theta \mathbb E[\rho(M_{\text{read},\theta})]$ to coincide with, or even to be positively correlated with, a policy that also maximizes $F_{\text{grounding}}$, because nothing in the objective constrains that correlation to hold, and a spec that is well-formed, internally consistent, and easy for $M_{\text{code}}$ to implement faithfully already satisfies every term in $\rho$ whether or not it accurately represents the paper it claims to summarize, a failure mode already observed and named in this project prior to any RL training against it. An unoptimized, merely prompted policy has weak incentive to exploit this gap; a policy under gradient-based optimization against $\rho$ has every incentive the objective supplies, which is exactly $\rho$ and nothing else, so the gap is not a cosmetic omission that RL training happens to leave unaddressed, it is a specific, exploitable direction in the reward landscape that RL training will find and climb unless $F_{\text{grounding}}$ is added to $\rho$ before $M_{\text{read}}$ is trained rather than after. A closed-form, label-free candidate exists for at least the fabrication component of $F_{\text{grounding}}$: the extraction schema already requests and receives a source span for the overwhelming majority of extracted steps and assumptions, measured this session at 98.4% and 98.8% coverage respectively across 557 real specs, and the full paper text is already in scope inside the reader specialist at the moment the spec is produced, so a fuzzy match of each claimed span against that text, computed and persisted at extraction time rather than reconstructed later since the text itself is not currently retained, supplies a deterministic, zero-labeling term that closes the fabrication half of the gap while leaving the harder half, a genuine quote attached to a mischaracterized claim, exactly as open as it already is today. This is a bound on what the fix buys, not an argument against building it: the current system checks neither failure mode, closing one of the two is a strict improvement, and it is the only one of the two with a free, deterministic check currently visible.

A fourth bottleneck is a resource-cost asymmetry across the pipeline that runs in the opposite direction from the attribution-cleanliness gradient, which makes the natural training order counterintuitive rather than obvious. One GRPO round for specialist $M_j$ requires $G$ independent rollouts per context to be carried forward through every stage downstream of $j$ before a reward is observed at all, since the reward is terminal and delayed by construction; write $C_{j:L}$ for the compute cost of running stages $j$ through the end of the pipeline once. Round cost scales as $K \cdot G \cdot C_{j:L}(j)$, and $C_{j:L}$ is largest for the earliest specialist and smallest for the latest one, so $M_{\text{query}}$, sitting at $j=1$, pays for retrieval, extraction, coding, execution, and validation on every single sampled rollout, while a specialist near the end of the pipeline pays only for what remains after its own decision. $M_{\text{query}}$ is simultaneously the most expensive specialist to generate one round of training signal for and the one whose signal is most attenuated by everything that happens after it, five more stages of randomness standing between its action and the number it gets scored on, while a late-pipeline specialist gets cheaper samples with less intervening noise between action and reward. This is why $M_{\text{query}}$ being the first specialist actually trained in this project was not the cheapest or cleanest starting point available, it was simply the one already built; a plan optimizing for signal quality per unit of A100 time would have started at the opposite end of the pipeline, and the fact that $M_{\text{code}}$'s reward machinery was independently assessed this session as the most mature and hardest to game is consistent with, not incidental to, its being closer to the terminal reward.

All of the above is pipeline-position mathematics, independent of hardware; the A100 constraint is where it becomes a scheduling problem with a number attached rather than an abstract concern. The measurements already taken this session, not projected, are that a 4-bit-quantized 8B parameter base model occupies roughly 4 to 5 gigabytes, that the two standard QLoRA memory levers, gradient checkpointing and dropping the reference model entirely, were both already active by default and still insufficient once completion length was pushed from 700 to 900 or 1100 tokens, that the crash site in every one of those failures sat inside the transformer's own forward pass during training, not inside generation, and that the observed failure state, on the order of 39.48 of 39.49 gigabytes allocated with roughly seven megabytes free, is the signature of genuine peak-memory exhaustion rather than allocator fragmentation, which rules out the cheap fixes and leaves the actual total sequence length, prompt plus completion, as the binding constraint: measured this session at a mean prompt length of roughly 480 tokens stacked underneath a completion budget nominally capped at 700, giving an effective sequence length near 1100 to 1200 tokens already at the setting judged safe, with three-quarters of that completion budget on average spent on unstructured reasoning prose before the model begins answering at all, at a measured rate of 98 percent of sampled completions across the full run. One A100 at this quantization and this sequence-length regime supports training exactly one specialist's parameters at a time with headroom to spare only because the four other specialists in the current design are hosted and cost nothing locally; the moment a second specialist's weights need to be locally resident and locally trained, whether $M_{\text{code}}$ joins $M_{\text{query}}$ as a second full base-model-plus-adapter load or as a second adapter sharing $M_{\text{query}}$'s already-resident base model, the arithmetic changes. A second full base model roughly doubles the fixed 4-to-5-gigabyte floor and, more importantly, doubles the number of forward passes with their own activation and KV-cache spikes contending for the same shrinking margin that already produced near-total exhaustion once; this does not fit on one A100 at anything like the sequence lengths already found necessary for one specialist alone, and reducing sequence length further to make room directly trades away the query specialist's own already-thin operating margin. Sharing one base model across two adapters instead avoids the doubled fixed floor, at the cost of a different constraint that is not a memory constraint at all: a LoRA adapter is a low-rank perturbation of a frozen base, and there is no guarantee, only an empirical question not yet measured for this base model, that two qualitatively different tasks, generating a compact retrieval query and generating a syntactically and semantically constrained executable program, both sit within reach of a rank-16 perturbation of the same frozen prior, whereas the base model's own pretraining distribution may simply be closer to one of those tasks than the other; a base model whose unadapted prior is already poorly suited to code synthesis may need either a higher rank, which reintroduces some of the memory cost the sharing was meant to avoid, or a different base model entirely, which reintroduces the doubled-floor problem in a different form. Sharing one base model also introduces a concurrency hazard that has nothing to do with total memory: which adapter is active is global, mutable state on one Python object, not a per-request property, and ARIA's own design runs $K \times G$ rollouts concurrently within a single round, twelve in the runs already completed, so if a query-policy rollout and a coding-policy rollout are ever in flight at the same physical instant needing different adapters active, they race on the same object, and the correct fix is serialization of adapter switches, which is a real, adopted piece of engineering, not overhead invented for its own sake, but it converts what would have been full concurrency across twelve rollouts into partial concurrency bounded by however many rollouts happen to need the same adapter at once, a real throughput cost traded for the memory saving, not a free lunch on either side of the trade.

Moving from one A100 to $N$ resolves exactly one of the bottlenecks above and leaves the rest standing, sharpened rather than removed. The nonstationarity theorem and its isolated-arm corollary are unaffected by hardware entirely; more GPUs let the isolated arms run concurrently instead of sequentially, four specialists each on their own device, each against a frozen baseline stack, but the mathematical requirement that the other three stay frozen during any one arm's training round does not relax with $N$, and running all five specialists' parameters as simultaneously live and mutually adapting is exactly as invalid on $N$ devices as on one, only faster to reach an invalid result. The non-compensable-cascade masking problem is unaffected by hardware entirely; it is a statement about how the reward function composes across specialists, not about compute. The reward-hacking exposure specific to $M_{\text{read}}$ is unaffected by hardware entirely; more GPUs make it cheaper to run more rollouts against an unfixed reward, which accelerates finding the exploit, not the fix. What genuinely changes at $N \geq 4$ is the adapter-sharing trade-off from the paragraph above: with one device per specialist, there is no shared mutable adapter state and no serialization hazard, each arm gets full, uncontended concurrency across its own $K \times G$ rollouts, and the memory argument for adapter sharing on a single device simply does not apply once each specialist has a device of its own. What does not change, and is easy to miss, is total compute cost: parallel arms bound wall-clock time by the slowest arm rather than by the sum of all four, since $M_{\text{query}}$'s $C_{1:L}$ dominates every other arm's cost per rollout, but the total number of GPU-hours actually consumed and billed still sums across arms, four devices running for as long as the slowest one takes is four times the resource draw of one device doing the same work sequentially in the time the slowest arm alone would need, not a savings, only a different axis being optimized, wall-clock instead of total spend, and on a rented A100 fleet those are genuinely different currencies. A second thing that changes only partially at $N$ devices is the composition phase: once four specialists are each independently trained and independently evaluated against their own frozen baseline, combining them into $E_{\text{all-FT}} = (\widetilde M_{\text{query}}, \widetilde M_{\text{read}}, \widetilde M_{\text{code}}, \widetilde M_{\text{critic}})$ for a joint evaluation is a fifth configuration distinct from any of the four training arms, and nothing already argued guarantees $\Delta_{\text{all}} = \sum_j \Delta_j$; interaction effects are not a hardware phenomenon either, a better query genuinely can retrieve papers the reader was never trained against, a more thorough spec genuinely can exceed context budgets the coder was never trained against, and the composed pipeline's actual behavior is an empirical question this design cannot answer in advance, only set up to measure honestly once each isolated arm's own effect is already established on its own terms.

The bottlenecks collected here are not an argument against the philosophy, they are the content the philosophy is missing before it is a plan. Whether a substitution like this holds is already documented in the current literature as method- and reward-sensitive rather than automatic, small models trained end-to-end by reinforcement learning do reach or exceed much larger hosted models on narrow reasoning and agentic tool-use tasks in multiple independently reported settings, and the same family of methods is separately documented to fail outright under specific reward and learning-rate conditions in at least one controlled study of a small-model web agent. That inconsistency across the literature is not a reason to expect ARIA's own extension of the pattern to a five-stage, non-compensably gated, delayed-reward pipeline to be safe by analogy; if anything the additional structure here, upstream nonstationarity between specialists, cascade masking of downstream specialists' true effects, an already-documented reward-measurement gap specific to one specialist, and a resource-cost gradient that runs opposite to the signal-quality gradient, gives this setting more distinct ways to fail than the single-turn tasks most of that literature studies, and every one of those ways to fail is stated above as a specific, checkable mathematical condition rather than a vague risk, which is exactly the form a bottleneck has to take before it can be either fixed or shown to not apply.
